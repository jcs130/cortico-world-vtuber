# 连续语音与音色排查

同一条自然语句里的 `<动作>` 使用一次流式合成。动作按播放时间轴执行：开启逐字对齐时使用对齐结果；关闭时使用已有语速估计，收流后用真实总时长修正。估计不等于逐字精确对齐，也不启动额外模型调用。`【动作】` 的阻断语义保留。

这减少了内联表演导致的独立合成次数，并保留句内韵律连续性。固定参考音频、种子和模式仍不能保证不同文本有相同的音高、情绪或听感。不能把音色设置相同当作主观质量已通过。

排查时对齐：说话轮次与原文 → 分段请求 → 参考音频哈希、模式和种子 → 原始 PCM 哈希与采样率 → 声卡实际播放采样率。声音只做本地短窗采样；不要把音频写进 Agent 记忆或默认永久保存。

2026-10-14 的 N1 样本中，54 次请求使用同一参考、种子 42 和 ref_continuation；7 段现役 PCM 与后端哈希一致。存在内联动作将一句话切成两个独立请求的情况。连续合成的短窗对照只支持减少此类重新起声，不能证明全部句间差异已经解决。

## 远程语气与句尾语气词

OpenAI 分块 WAV 默认只发送标准语音字段。确认目标模型支持 `instructions` 后，显式设置 `ttsTransport.supportsInstructions: true`，才会传递单段的文字语气元数据。可选 `ttsTransport.defaultInstructions` 提供默认说话方式；单段描述覆盖默认值，显式空字符串取消本地默认。未提供描述时沿用服务端默认。两项均需重新加载扩展。

描述最多 64 字，不含括号、标签或换行，只描述说话方式。它不会加进 `input`、字幕或参考转写，不会传出本地参考音频和生成参数。此开关是部署者对服务能力的显式声明，不会额外扫描端口、探测其他接口或调用模型。服务不支持时保持关闭；没有标准化回执的服务也不能仅凭 HTTP 200 就宣称语气已生效。支持 `x-tts-prompt-mode` 的服务会将模式留在单次请求 trace 中。

2026-10-18 的 Q5 末尾“喵”样本以原始文本重合成，PCM 哈希与生产记录完全一致；整条请求只有一个模型分段。因此该样本的听感不能归因于额外拼接猫叫文件。对照包括轻声读音和独立语气描述；语气控制会切换模型的 prompt 模式，保留同一参考不等于听感完全相同。默认保持原配置，需试听确认再采用。相关记录在部署侧短窗诊断中保存。
